# posts/book.md をブクログの本棚に同期する

`posts/book.md` を唯一の情報源(source of truth)として、ブクログの本棚を追従させる。差分だけを書き込むので、再実行しても重複登録は起きない。

## 前提: ログイン済み Chrome へのアタッチ

ブクログの書き込みにはログインが必要なので、ユーザーの普段の Chrome にアタッチして操作する(**attach-local-chrome** スキル参照)。

```bash
npx -y @playwright/cli@latest attach --cdp=chrome
```

事前にユーザー側で `chrome://inspect/#remote-debugging` の「Allow remote debugging for this browser instance」を有効にし、初回の接続許可プロンプトを承認してもらう必要がある。`chrome` セッションが無い場合スクリプトは案内を出して中断する。終了時は `npx -y @playwright/cli@latest --s=chrome detach` で切り離すこと(`close` はユーザーのブラウザを閉じてしまうので使わない)。

## 実行

```bash
python3 "$CLAUDE_SKILL_DIR/sync.py" --dry-run   # 差分の確認だけ
python3 "$CLAUDE_SKILL_DIR/sync.py"             # 実際に反映
```

| オプション | 意味 |
|---|---|
| `--book-md PATH` | 入力ファイル(既定 `posts/book.md`) |
| `--dry-run` | 差分を表示するだけで書き込まない |
| `--no-update` | 新規追加のみ行い、既存本の読書状況は触らない |

\*\*初回や本を大量に追記した直後は必ず `--dry-run` を先に実行し、追加・更新の内容をユーザーに見せて確認を取ってから本実行すること。\*\*外部サービスへの書き込みなので、意図しない大量登録を避ける。

## book.md からのマッピング

| book.md | ブクログ |
|---|---|
| `- [題名](URL)` | アイテム(ASIN / ISBN-10 で特定) |
| `WIP` マークあり | 読書状況 `いま読んでる` |
| `WIP` マークなし | 読書状況 `読み終わった` |
| 見出し階層 | **使わない**(タグは付けない。ユーザーの方針。ブクログ側に既にあるタグは消さずに残す) |
| 感想文 | **転記しない**(ユーザーの方針。レビュー欄・読書メモ欄とも空のまま) |

同じ本が複数の見出しに載っている場合(例: `## 自分の人生に強い影響を与えた本` と `## 技術書`)は、アイテムID単位でまとめる。どれか1つでも `WIP` なら `いま読んでる` になる。

`booklog.jp` へのリンク(記載方針の節にある本棚リンク)は本ではないので解析対象から外す。外さないと本棚ページ本文の ISBN を拾って別の本の ID に化ける。

読了日は埋めない — 感想文中の年は「2019年ごろ」のように曖昧なものが多く、誤った日付を残さないため。

## 処理の流れ

1. `posts/book.md` を解析(題名 / URL / WIP)。
1. 題名 → アイテムID を `ids.json` から引く。未知のものだけ解決する:
   - `amzn.asia/d/...` は **1ホップのリダイレクト先**に ASIN が入っている(`curl -w '%{redirect_url}'`)。全文を追うと Amazon に弾かれるので1ホップに留める。
   - 出版社ページは**本文**から ISBN を拾う。URL 中の数字は製品コードで ISBN と1桁違うことがある(例: SBクリエイティブ)。本文取得に失敗したら URL 側にフォールバック。
1. 解決した ID が `/item/1/{id}` で 200 を返すか実在確認する。
1. 各アイテムの編集ページ `/edit/1/{id}` から現在の読書状況を読んで差分を取る(編集フォームが無ければ未登録)。
1. 未登録 → `POST /api/book/add` で1冊ずつ追加、読書状況の差分 → `POST /edit/1/{id}` で個別更新。
1. 解決した ID を `ids.json` に書き戻し、最後にもう一度編集ページを読んで反映を確認する。

## ids.json

題名 → アイテムID の対応表。自動解決の結果がここに溜まるので、2回目以降は既知の本の再取得をしない。

- `resolved`: 題名 → ASIN / ISBN-10。
- `skipped`: ブクログに存在しないと確認済みの本と、その理由。毎回の解決試行を避けるためのもの。

自動解決に失敗した本があると、スクリプトはブクログの書名検索候補を並べて終わる。**候補から正しいものを選んでユーザーに確認し、`resolved` に手で追記する**(同人誌などブクログに無い本は `skipped` に理由付きで入れる)。ここは自動判定させない — 版違いや別シリーズを掴みやすいため。

## ブクログ側の仕様メモ

- **エクスポート(`/export`)は使えない**: 2026-10時点で「バックグラウンド処理 → 登録メールにダウンロードリンク送付」方式に変わり、ページ上にリンクが出なくなった。代わりに `/edit/1/{id}` を1冊ずつ引く。未登録アイテムでも 200 が返るが `create_on_d` を含む編集フォームが無いので、それで登録有無を判定する。
- **CSV まとめて登録(`/input/file`)は使えない**: メールアドレス未認証のアカウントでは「メールアドレスが未認証です」と出て何も登録されない(HTTP は 200 なので応答コードでは気づけない)。
- **追加は `POST /api/book/add`**: 本の詳細ページの「本棚に登録」ボタンが叩く XHR。body は `service_id=1&id={ID}&status={1-4}&secret=0`(urlencoded、`x-requested-with: XMLHttpRequest`)。`status=0` だと読書状況なしで入るので必ず値を渡す。既存アイテムに投げても重複しない。
- **読書状況の変更は `POST /edit/1/{ID}`** (`_method=edit`) で行う。ラジオ `status_1_{ID}` の値は 読みたい=1 / いま読んでる=2 / 読み終わった=3 / 積読=4。編集フォームの既存値をすべて拾い直してから該当項目だけ差し替えること(登録日時やタグを消さないため)。
- `eval` は**現在開いているページ上**で走る。相対 `fetch` を booklog に向けるため、操作前に必ず booklog へ遷移させる(他サイトを開いたまま叩くと全部 404 になる)。

## 注意

- ブクログ側は大量データの連続操作を控えるよう明記している。1冊ごとに sleep を入れてある。
- 同人誌(BOOTH / 技術書典 / 個人出版)は ISBN が無くブクログに該当アイテムが存在しない。ISBN 登録では扱えないので、どうしても入れたい場合は[オリジナルアイテム登録](https://booklog.jp/item/input)を手動で使う。
- book.md 内で同じ URL が別の本に使い回されていると誤登録になる。スクリプトは題名をキーにするので `ids.json` 側で正しい ID を持てば救えるが、**book.md の URL 自体を直すのが本筋**。
